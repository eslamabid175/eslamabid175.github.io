💡 الفكرة في جملة: من غير بيئة، كل session بتبدأ من الصفر: الـ agent بيخمّن شكل المشروع، ويقولك «خلصت» من غير ما يشغّل حاجة، وينسى كل اللي اتعمل بعد /clear. البيئة بتديله ذاكرة وأدوات وطريقة شغل وحدود، فيبقى زميل بيتحاسب على شغله.
🗺️
ذاكرة المشروع
CLAUDE.md قصير (خريطة مش موسوعة)، وrules بتتحمّل بس لما يلمس ملفات معينة، وdocs بيقرأها وقت ما يحتاج. وقاعدة ثابتة: لو الكود والـ doc اختلفوا، الكود يكسب وتتصلّح الـ doc في نفس التغيير.
👀
عينين وإيدين

🔁
طريقة شغل ثابتة

🛡️
حدود وأمان
Hooks وpermissions بتمنع قراية الـ secrets، وبتسأل قبل git push أو rm -rf أو deploy، وبتمنع الـ E2E إنه يضرب على production.

// 04 — MCP Servers

MCP لـ Flutter

💡 أول مشكلة هتقابلك — الـ PATH: Claude Code بيشغّل الـ MCP servers بـ PATH صغير، فـ Flutter اللي متسطب من الـ IDE أو FVM، و~/.pub-cache/bin، وNode من nvm، وadb بيطلعوا «command not found». الحل اللي ثبّته في كل مشروع: كل server يقوم من .claude/mcp/launch.sh، اللي بيدوّر على الـ SDK بالترتيب ده: FVM pin → PATH → $FLUTTER_ROOT → FVM default → common install dirs، وبعدين يعمل exec للـ server الحقيقي.
🎯
dart
الـ server الرسمي (dart mcp-server): analyze، LSP (definition / references)، pub، والاتصال بالتطبيق وهو شغال: hot reload، widget inspector، والـ runtime errors. (من Dart 3.12 أدوات زي run_tests وdart_format مقفولة by default، والـ tests بتتشغّل بـ flutter test.) في مشروع الشغل قفلت أدوات الـ format/fix لأن ملفات كتير مش متفرمتة، والـ format لملف كامل بيدفن الـ diff الحقيقي.
🕹️
marionette
بيسوق debug build شغال عن طريق الـ VM service: connect، get_interactive_elements، tap، enter_text، screenshots، logs، hot reload. محتاج marionette_flutter و binding جوه kDebugMode بس.
🧪
patrol
patrol_mcp بيشغّل E2E من patrol_test/: run، status، screenshot، native tree. في monorepo بعمل instance لكل app بـ PROJECT_ROOT بتاعه. Emulator بس، وعلى dev API بس.
📱
mobile
@mobilenext/mobile-mcp: يتحكم في الـ emulator: عناصر الشاشة، taps، كتابة، screenshots، logs، وكمان system dialogs زي طلب الـ permissions اللي Flutter نفسه مش شايفها.
🌐
playwright
Flutter web في متصفح حقيقي (لوحات الأدمن مثلاً). التريكة: دوس على flt-semantics-placeholder الأول عشان الـ semantics tree يتفعّل وتعرف تعمل snapshot وتدوس بالـ role.
🔥
firebase
أدوات Firestore / Auth / FCM / Crashlytics. مقفول by default لأنه بيكلّم project حقيقي. في مكسبي production «hands-off»: الـ agent يعرض preview والأمر، وأنا اللي أنفّذ أي write.
📚
context7
docs محدّثة لـ packages الـ pub.dev وغيرها، بدل ما الموديل يفتكر API قديم من الـ training.
🐍
django (في مشاريع الـ backend)
mcp-django للـ routes والـ models والـ management commands، بس على test settings بـ SQLite في الميموري، في venv منفصل عشان venv المشروع يفضل مطابق لـ production. الـ introspection مسموح، والـ shell بيسأل.

الـ .mcp.json — انسخه زي ما هو

json { "mcpServers": { "dart": { "command": "bash", "args": [".claude/mcp/launch.sh", "dart", "mcp-server", "--disable", "create_project"] }, "marionette": { "command": "bash", "args": [".claude/mcp/launch.sh", "marionette_mcp"] }, "patrol": { "command": "bash", "args": [".claude/mcp/launch.sh", "dart", "pub", "global", "run", "patrol_mcp"], "env": { "PROJECT_ROOT": ".", "PATROL_FLAGS": "--dart-define=API_BASE_URL=<YOUR_DEV_API_URL>", "PATROL_DEFINES_FILE": ".claude/local/e2e-defines.json", "SHOW_TERMINAL": "false" } }, "mobile": { "command": "bash", "args": [".claude/mcp/launch.sh", "npx", "-y", "@mobilenext/mobile-mcp@latest"] }, "playwright": { "command": "bash", "args": [".claude/mcp/launch.sh", "npx", "-y", "@playwright/mcp@latest"] }, "firebase": { "command": "bash", "args": [".claude/mcp/launch.sh", "npx", "-y", "firebase-tools@latest", "mcp", "--dir", "."] }, "context7": { "command": "bash", "args": [".claude/mcp/launch.sh", "npx", "-y", "@upstash/context7-mcp@latest"] } } }
✅ اختبره من غير restart: .mcp.json بيتقري أول الـ session بس. عشان كده كتبت mcp_probe.py (Python standard library بس): بيكلّم كل server بـ JSON-RPC على stdio، يعمل initialize وtools/list، ويطبع ok أو FAIL لكل واحد. و--call NAME JSON بيشغّل tool من الـ shell ويحفظ الصور.
dart // lib/main.dart void main() { // Marionette needs this binding; never ship it in release. if (kDebugMode) MarionetteBinding.ensureInitialized(); runApp(const MyApp()); } // lib/core/config/api_config.dart (the file e2e-guard.sh checks) // API URL overridable from the command line, so E2E can target a dev API: class ApiConfig { static const baseUrl = String.fromEnvironment( 'API_BASE_URL', defaultValue: '<YOUR_PROD_API_URL>', ); }
⚖️ الـ Trade-off: patrol_mcp بيختار التليفون الحقيقي الأول لو متوصل، وكل run بيمسح داتا التطبيق. عشان كده الـ E2E عندي emulator بس (فيه سكريبت بيرفض أي -d مش emulator-N)، والـ emulator بياخد حوالي 5GB رام، فالـ patrol servers التقيلة بتبقى مقفولة by default وبفتحها بـ /mcp وقت الحاجة.

💡 قسّم حسب الحجم: تعديل صغير (ملف واحد، fix واضح) ← investigate ← تعديل مباشر ← verify-change. أي حاجة أكبر (feature جديدة، أكتر من layer، تغيير schema أو API) ← /plan ← أراجع الخطة ← /execute. أو /feature يعمل الاتنين من غير وقفة الموافقة.

الـ Agents: كل واحد ليه دور وموديل

model: strongest · kit: opus
architect
بيقرا الـ rules والـ docs والكود وبياخد كل القرارات التقنية. الـ output الوحيد: .claude/plans/current-task.md بأقسام ثابتة: Goal، Technical Decisions (ومعاها البدائل اللي اترفضت)، Files To Modify / NOT To Touch، Implementation Steps، Acceptance Criteria، Docs To Update. عمره ما بينفّذ.
model: opus · kit: inherit
executor
بينفّذ الخطة بالظبط. أول حاجة snapshot لـ git status عشان ما يلمسش شغلي. ترتيب ثابت: schema → data → domain → cubit → UI → l10n، ولازم يشغّل أوامر التحقق ويحط الـ output الحقيقي. ولو لقى تناقض معماري بيقف (STOP) وما يخمّنش.
model: strongest · read-only · kit: opus
reviewer
بيراجع الـ git diff الحقيقي، مش تقرير الـ executor. أول سطر لازم يكون VERDICT: APPROVED أو VERDICT: CHANGES REQUIRED ومعاه «Fix List For Executor» بترجع للـ executor بالحرف. بحد أقصى 2 rounds.
model: inherit · plan mode
investigators
read-only للبحث الواسع: مين بينادي الـ endpoint ده؟ الـ cubit ده مستخدم فين؟ الرد أقل من 60 سطر وفيه path:line، فالـ context الرئيسي يفضل نضيف.
model: sonnet
test-runner / gate-runner
بيشغّل الأوامر اللي اتقالت له بس، ويرجّع سطر لكل أمر وأول الـ failures. الـ logs الطويلة ما تدخلش الـ context الغالي.
read-only · kit: sonnet
ui-auditor
بيراجع الـ UI على design/tokens.md: dark mode، RTL، مفاتيح l10n في كل لغة، loading/empty/error، accessibility (48dp، text scale 1.3)، والـ shared widgets. كل finding بـ severity وpath:line والـ fix بالظبط.
md --- name: architect description: Lead architect for this Flutter project. Use for any non-trivial task BEFORE code is written. Reads CLAUDE.md, the rules and the code, makes every technical decision, and writes the implementation plan to .claude/plans/current-task.md. Never implements. tools: Read, Grep, Glob, Bash, Write model: opus --- You are the lead architect. You THINK, ANALYZE, DECIDE and PLAN. You never implement: the `executor` agent carries out exactly what you decide, and the `reviewer` agent checks the result against your plan.

ذاكرة بتعيش بعد /clear والـ compaction

💡 الفكرة: الـ progress ما يتحطش في الـ chat ولا في الـ auto-memory. بيتحط في ملف: .claude/progress/CURRENT.md. الـ skill task-state بيعمل start / update / done، والـ SessionStart hook بيطبع الملف تاني بعد startup أو resume أو clear أو compaction، وcontinue-task بيقارنه بـ git ويعيد آخر تحقق رخيص ويكمل من غير ما يعيد خطوات خلصت. ولما المهمة تخلص بيتنقل لـ progress/archive/YYYY-MM-DD-slug.md.

Skills بستخدمها كل يوم

🔎
investigate / trace-api
trace read-only قبل أي fix: route → page → cubit → repository → data source، وفي مشاريع الـ backend لحد Django urls → view → serializer → model. ومعاه git log -S للتاريخ. الـ output: findings بـ path:line، root cause، risks، next action.
✅
verify-change / verify
جدول check | command | result: codegen، flutter analyze (الجديد بس)، أقرب tests، arb parity، فحص إن مفيش ملفات تانية اتلمست، ومفيش secrets أو debug. وقسم «Not verified» بالسبب.
🧱
gates بـ baseline
مشروع قديم فيه analyzer issues من زمان؟ gates.sh بيقارن بـ .claude/baseline/ ويفشل على الـ issues الجديدة بس، ويقولك كمان على اللي اتصلّح.
🕸️
code graph
سكريبت Python من غير dependencies بيعمل index: routes → pages → cubits → API calls، وفي مشروع الشغل بيربط calls الـ Flutter بالـ Django endpoints عبر الـ repos. بيجاوب «لو غيّرت ده إيه يتكسر» من غير ما يقرا الـ repo كله. وفي مكسبي: لو --impact لمس أكتر من 3 modules يبقى لازم /plan.
🔂
work loop (/next-task)
في مكسبي: /loop بياخد أول item من QUEUE.md أو PLAN.md، يحدد حجمه، ينفّذه، يشغّل /verify، ويسجّل، ويخلص بسطر واحد LOOP: DONE|PROGRESS|QUEUE_EMPTY|BLOCKED|GATE_RED|CAP. وفيه حد أقصى للـ iterations.
🧑‍⚖️
review-changes workflow
مراجعة عدائية: agent يحدد الـ scope، وبعدين reviewers بالتوازي لكل بُعد (correctness، architecture، data/API، UI/l10n، security)، وبعدين 2 skeptics لكل finding. في الـ Kit الـ finding بيتشال بس لو الاتنين نفوه.

الـ Hooks: حواجز وتذكير

🧭
session-env.sh
SessionStart: بيكتب PATH exports في $CLAUDE_ENV_FILE عشان كل أمر Bash يلاقي Flutter (ومعاه FVM)، وأدوات الـ pub-cache، وNode، وadb. لو مش لاقي حاجة يعدّيها بهدوء ومايوقّعش الـ session.
🧠
session-start.sh
SessionStart (startup | resume | compact | clear): بيرجّع CURRENT.md لو فيه مهمة شغالة، وأي plan مفتوحة، والـ branch وعدد الملفات المتعدلة مع جملة «ده شغل المستخدم، ما ترميهوش». في مشروع الشغل كمان بيعدّ الـ deploys اللي لسه ما نزلتش ويقول لو الـ code graph قديم.
🚧
guard.sh
PreToolUse (Bash): deny لطباعة .env وkey.properties والـ keystores والـ service accounts. ask قبل git push، reset --hard، rm -rf، firebase deploy، pm clear، patrol من غير -d emulator-N، وdart format ..
🧯
e2e-guard.sh
PreToolUse (mcp__patrol__run): بيسأل لو الـ dev API لسه placeholder، أو ملف الـ API مش بيستخدم String.fromEnvironment (يعني الـ run هيضرب production)، أو patrol مش في الـ pubspec، أو فيه تليفون حقيقي متوصل.
✍️
after-edit.sh
PostToolUse (Edit | Write): dart format وdart analyze للملف اللي اتعدّل بس، والـ errors بترجع لـ Claude كـ context. وتذكيرات مرة واحدة في الـ session: build_runner لو فيه part '*.g.dart'، المفاتيح في كل ملفات الـ .arb، schema bump، pub get.

ركّبها في مشروعك

📦 Flutter Claude Kit: نسخة عامة من البيئة دي، من غير أي اسم شركة أو host أو app id. فيها 7 MCP servers، و6 agents، و15 skill، و5 hooks، وأدوات الـ probe والـ gates. كل اللي عليك تملا الـ <PLACEHOLDERS> وتشيل اللي مش محتاجه.
⬇ flutter-claude-kit.zip تصفّح الـ Kit على GitHub README.md .mcp.json CLAUDE.md settings.json
  1. المتطلبات: Claude Code، وFlutter فيه Dart 3.12 أو أحدث (عشان dart mcp-server؛ لو أقدم شوف الـ README)، وNode 20+، وAndroid SDK ومعاه emulator، وpython3. واختياري: Patrol CLI وpatrol_mcp وmarionette_mcp.
  2. انسخ الـ Kit في root المشروع بـ cp -rn عشان ما يكتبش فوق ملفاتك. لو عندك CLAUDE.md أو settings.json قبل كده، ادمجهم بإيدك.
  3. املا الـ placeholders: اسم المشروع والـ stack والأوامر في CLAUDE.md، والـ dev API في .mcp.json، والـ architecture في rules/mobile.md، وملف الـ API في e2e-guard.sh. لو monorepo كرر الـ patrol entry لكل app.
  4. خلّي الـ API URL يتغير من بره بـ String.fromEnvironment('API_BASE_URL')، وإلا الـ E2E هيضرب production.
  5. اعمل baseline للـ analyzer issues الحالية: bash .claude/bin/gates.sh --update-baseline، فالـ gates تفشل على الجديد بس.
  6. اتأكد: افتح claude، وافق على الـ MCP servers، و/mcp. أو من الـ shell: python3 .claude/bin/mcp_probe.py. و/env-doctor بيفحص الباقي.
  7. اعمل commit للـ Kit (ما عدا اللي في .claude/.gitignore) عشان فريقك ياخده.

Lessons & Trade-offs

💸
الـ tokens فلوس
الموديل الأقوى للقرار والمراجعة بس، والتنفيذ بـ Opus، والشغل الميكانيكي (tests، gates) بـ Sonnet. الـ investigators بيرجّعوا أقل من 60 سطر، والـ logs ما تدخلش الـ context. وCLAUDE.md قصير لأنه بيتحمّل كل session.
🧺
skills كتير ≠ أحسن
نزّلت حوالي 32 skill جاهزة ومعظمها ما اتستخدمش، وكانت بتاكل context. 15 skill صغيرة مكتوبة على مقاس المشروع أنفع بكتير. وبراجع كل فترة أنهي skills بتتستخدم فعلاً.
📄
الـ docs بتقدم
doc غلط أخطر من مفيش doc، لأن الـ agent بيصدّقه. الحل: «الكود يكسب، صلّح الـ doc في نفس التغيير»، وقسم Docs To Update في كل خطة، وcheck-docs.py للينكات والمسارات الميتة، وworkflow بيعمل fact-check لكل doc بـ agent مستقل.
🔐
الـ agent ما يشوفش secrets
deny لقراية .env والـ keystores والـ service accounts، والـ test accounts في ملف شخصي gitignored بيتضاف للـ flags من غير ما يتقري. وأي write على production: الـ agent يعرض preview والأمر، وأنا اللي أنفّذ.
🧾
مفيش «خلصت» من غير دليل
الـ executor لازم يحط output الأوامر الحقيقي، والـ reviewer بيبص على الـ diff مش على التقرير. وتستات الـ Django بتشتغل على SQLite في الميموري، مش على داتا حقيقية.
🔌
الشغل الطويل بيموت
restart للـ session قتل agents كانت شغالة في workflow. الحل: كل agent يكتب progress-<role>.md وكل مهمة كبيرة ليها فولدر فيه STATE.md، فأي حد يكمل من مكان ما وقف.
⚖️ الـ Trade-off الأكبر: البيئة نفسها كود لازم يتصان: hooks وskills وdocs بتقدم مع الوقت (لسه فيه agent في مكسبي بيتكلم عن format hook اتشال). عشان كده بخلّي كل حاجة صغيرة وقابلة للفحص: mcp_probe للـ servers، check-docs للـ docs، و--check للنسخة المشتركة اللي بيتشال منها الـ state الشخصي.

اختبر نفسك

🧪 جاوب في دماغك الأول، وبعدين دوس على السؤال
الـ MCP server بيقول «dart: command not found» مع إن Flutter شغال في الـ terminal عندي. ليه، وإيه الحل؟

لأن Claude Code بيشغّل الـ stdio servers بـ PATH صغير مش بتاع الـ shell بتاعك. الحل إن كل server يقوم من wrapper زي launch.sh بيدوّر على الـ SDK والـ pub-cache وNode وadb ويضيفهم للـ PATH، وبعدين أختبره بـ mcp_probe.py من غير restart.

عملت /clear في نص مهمة كبيرة. الـ agent هيعرف يكمل إزاي؟

من .claude/progress/CURRENT.md: الـ SessionStart hook بيطبعه تاني بعد الـ clear، و/continue-task بيقارنه بـ git status وgit log، ويعيد آخر تحقق رخيص، ويكمل من الـ Next action من غير ما يعيد خطوات خلصت.

ليه الـ reviewer بيراجع الـ git diff ومش تقرير الـ executor؟ وليه حد أقصى 2 rounds؟

لأن التقرير ممكن يقول «عملت» واللي في الكود حاجة تانية؛ الـ diff هو الحقيقة. والحد الأقصى بيمنع loop لا نهائي بيحرق tokens: لو بعد 2 rounds لسه فيه مشاكل، يبقى غالباً المشكلة في الخطة نفسها وترجع للـ architect أو ليا.

إيه اللي يضمن إن E2E بالـ Patrol ما يضربش على production؟

3 طبقات: الـ API URL بيتغير بـ String.fromEnvironment والـ PATROL_FLAGS فيها الـ dev API، وe2e-guard.sh بيسأل لو ده مش متظبط أو فيه تليفون حقيقي متوصل، والتشغيل على emulator بس لأن كل run بيمسح داتا التطبيق.

الـ repo مليان analyzer warnings قديمة. إزاي أخلي الـ gate مفيد بدل ما يبقى أحمر على طول؟

أعمل baseline بالـ issues الحالية (gates.sh --update-baseline)، والـ gate يقارن بيها ويفشل على الـ issues الجديدة بس. والـ baseline ما يتحدّثش غير بموافقتي، عشان الـ agent ما يخبّيش مشاكل جديدة فيه.
